# 材料怎样按照当前架构生成读本

正式项目目录是 `LessonWeave`，公共规则保存在 `framework`，网站的调度入口是 `lessonweave/pipeline.py`，流程展示入口是 `/architecture`

## 每一步读取什么，保存什么

| 阶段 | 读取什么 | 保存什么 | 怎样检查 |
| --- | --- | --- | --- |
| 00 保存材料 | 用户提交的 PDF、网页地址或仓库文件 | `00_source/source.json` 与材料本地副本 | 实际文件、资源和获取状态 |
| 01.1 解析为材料树 | 本地原材料 | `01_tree/tree.json` | 提取内容、对象存在率、真实定位与材料层级 |
| 02 规划第 0 章与正文问题 | 完整材料树与学习目标 | `02_questions/questions.json`、逐项用途与差集 | 首轮同时规划，材料去向明确率与应讲解内容分配率均为 100%，有缺项才补 |
| 03 编排章节 | 问题及前置关系 | `03_chapters/chapters.json` | 每问恰好归属一次，第 0 章使用 `0.`，正文从 `1.` 开始，每个问题恰好归属一次 |
| 04 编写正文 | 当前问题、对应材料与必要背景 | `05_writing/work/sections/<section>/unit-<question>.json` | 校验新版字段与正文位置，写作上下文逐单元独立 |
| 05 补写承上启下 | 已完成的本节正文与前节真实正文 | 同目录下的 `bridge.json` 与 `extras.json` | 承上一段，前提与问题合成启下一段，易错点与练习回答当前内容 |
| 06 统一整理术语表 | 已完成的正文、承接、总结、易错点和练习 | 同目录下的 `glossary.json` | 名称由三个字段组装，定义、直观解释、案例各一段，局部符号保留定义范围 |
| 07 审查讲解 | 已生成字段、素材与实际引用 | 同目录下的 `review.json`、`coverage.json`、`writing-hints.json` | 脚本检查格式、缺字段和引用，集中修复实际缺项，不调用 AI 内容评分 |
| 08 交付阅读 | 书稿、来源对应与审查结果 | `05_writing/book.json` 或 `preview-book.json` | 检查通过后发布，待审预览保留实际问题 |

显示阶段号与磁盘目录分别管理，既有路径保留，`04_transitions` 现在由脚本计算章节位置与前后关系，真正的承接文字在正文完成后产生

## 新版正文怎样显示

`premise` 展开当前问题，每个 `explanation` 条目包含 `claim`、`reasoning`、`grounding`、`supplement` 四个完整自然段，作者按理解关系重复这一组，图片、源码、公式或表格放在该组的 `resources` 中

`result.answer` 回答当前问题，`result.generalization` 提炼带适用条件的可迁移结论，两者合成一个升华段，下一问由承接阶段负责

`writing_contract.py` 把这份结构化原稿转换为阅读器支持的正文块，四段组的 ID 按“组 ID 加字段名”派生，来源绑定继续指向实际显示的段落，转换只调整数据格式，完整原稿保存在单元文件中

旧书稿继续按旧结构读取，脚本不会把一个旧段落切成四段后宣称已经完成新结构，也不会为迁移架构调用模型重写现有正文

## 怎样以较小成本保证主体清楚

写作提示词要求作者先明确核心命题的主体、行为或状态、对象和成立条件，再写自然语言，切换主体时写出新主体，同一主体可以共享主语，条件、操作和普遍规律按层次分句

脚本批量扫描作者文字，明确的内部编号泄漏进入错误列表，疑似省略主体或逗号密集只写入提示列表，含糊提示不单独触发修复，不增加逐句字段、语法模型调用或语言专项审查，DDParser 保持关闭

这项检查用于减少明显的压缩表达，脚本对语法完整性的判断有局限，材料事实、推导是否充分、具体内容是否讲清由读者阅读实际正文判断，当前默认流程不调用独立 AI 内容评分

## 既有结果和笔记怎样保留

本次只更新实现、Schema、规则说明和架构展示，现有正文、历史、材料、覆盖记录与笔记保持原样，`05-test` 继续由用户测试，正式 ReadWeave 仓库仍由其负责的 agent 维护

框架版本以 `framework/architecture/contract.json` 为准，网页读取每个项目真实保存的文件，缺少新版产物时显示未生成，已有覆盖数字和失败记录继续按实际值显示
