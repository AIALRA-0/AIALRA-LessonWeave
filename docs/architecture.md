# 1 怎样从材料得到可阅读的内容

网站把输入与任务状态保存到 SQLite，后台按 00_source 到 05_writing 执行固定步骤，Codex 负责材料清点、规划、写作与独立审查

工作台的“流程与架构”按当前框架和所选项目显示各阶段的字段、渲染效果与实际检查规则，文件位置见 [架构页面说明](architecture-view.md)

每项语义调用使用独立上下文，作者和审查者使用不同请求，输入字节、材料图片、模型或推理档位变化时重新建立调用，字节相同的已完成请求复用保存结果

## 1.1 怎样控制返修

每个单元先生成一次，各单元并行提交，独立审查完成后集中记录问题，下一轮只向受影响任务提供反馈，初稿为第 0 轮，默认允许第 1 到第 3 轮修复，配置上限为第 4 轮

同一运行恢复时沿用原轮次，已经耗尽轮次的任务保留完整预览和真实失败记录，格式转换单独留档

## 1.2 怎样保存用户资料

LESSONWEAVE_DATA 保存材料、任务数据库、调用回执、各阶段结果和用户笔记，代码仓库保存公共实现与自编示例

旧项目可以登记为只读入口，自动流程使用新项目目录，公开仓库与私人运行数据分别管理

## 1.3 怎样判断覆盖

材料树检查保留的内容和资源，问题树检查材料归属，标题树要求每个问题恰好分配一次，写作审查逐项检查信息点及其 checks，程序据此计算 explained

脚本核对引用、正文块和版本是否存在，独立模型审查核对实际内容是否讲清，审查的材料和正文快照随结果保留

## 1.4 怎样切换后端

默认 CodexAdapter 直接调用本机 CLI，OpenAICompatibleAdapter 提供结构化接口接入，register_backend 可以登记其他执行器，每个适配器返回结构化结果与实际用量

Codex 通道已用于正式流程测试，其他后端由部署者配置密钥与模型后按相同合同验证，图片、Schema 与推理参数需要后端实际支持

## 1.5 怎样让 ReadWeave 接收结果

阅读包保存章节、问题、正文、术语、原材料、翻译和定位记录，独立组件在 Shadow DOM 中挂载并提供卸载方法，宿主负责登录、笔记与问答保存

Trilium 适配器使用 ETAPI 保存原生 book、text、code、render 笔记及附件，前端组件通过 renderNote 关系加载，学习笔记沿用宿主会话保存，正式 ReadWeave 项目由其维护者部署接入

## 1.6 怎样显示进度和结束任务

每个后台任务使用独立进程组，网站读取实际阶段产物与当前任务完成数，用户停止时先记录正在停止，再结束该进程组，确认退出后记录已停止

停止前已经完成的调用保留并可复用，尚未完成的调用保留部分回执，用户明确继续后重新执行未完成部分，迟到的成功结果继续保留停止状态

目录与项目使用软删除，恢复时沿原批次找回对应条目，笔记和生成文件保留，包含执行中项目的目录会先要求停止任务
