# 1 哪些公开发布问题需要持续避免

## 1.1 怎样保留回放器而排除私有归档

Git 忽略规则中的 archive/ 和 dist/ 会匹配各层目录，排除根目录产物时使用 /archive/ 与 /dist/，保留 framework/reader/archive 中的回放器和 media-vendor/katex/dist 中的公式排版器、字体与许可证

发布包应能打开带 Range 请求的 WACZ，并能取得回放器页面和 Service Worker，测试见 tests/test_web_archive.py

## 1.2 怎样避免发布机器路径与私有材料

开发用截图脚本、实验目录、账号、模型回执和生成读本留在仓库外；公开检查脚本使用可配置路径或临时目录，提交使用公开账户的 noreply 邮箱

发布前检查实际暂存内容和本次新增提交，保留许可证和第三方署名，文本扫描与图片内容分别核对

## 1.3 怎样保持原始 SVG 与阅读权限隔离

原始 SVG 作为源文件保留，笔记宿主中的预览继续沿用安全的图像表示；既有 SVG 预览测试需要持续运行，不能因为已经修复而删掉

## 1.4 怎样让脱敏源码仍能独立运行

源码包按用途保留运行文件，不能只按扩展名排除文档；模型提示词和技能文件也可能是程序实际读取的 Markdown 资源；脱敏时保留这些资源的原版内容与许可证，只排除私人数据、机器配置和历史记录

从实际待发布包构建并打开真实首次入口，核对页面引用的资源；原项目已改为客户端设置页时，沿用它的根页面，不为废弃路径补造一套模板；文件清单、覆盖源码和构建结果应对应同一份发布包

## 1.5 怎样让源码包的文件哈希与发布内容一致

在 Windows 上生成跨平台源码包时，归档命令显式使用 `git -c core.autocrlf=false archive`，避免本机换行设置改变归档字节；从实际压缩包重新读取文件，逐项核对覆盖清单，并保留完整许可证和构建资源

## 1.6 怎样核对带公式的选区与当前文章

公式排版后的 DOM 可能把同一公式显示成多个文本节点，保存与恢复选区时使用同一份公式源码和字符映射；切节开始就清除旧文章归属，等新文章准备好再绑定操作，测试时延迟网络请求并用真实鼠标选择，不能只核对最终页面标题

## 1.7 怎样保留共享文章里改过的媒体

阅读器给共享文章补媒体工具栏时，从当前文章读取表格、公式、图表、图片、代码与图注，不能拿旧生成 JSON 重建内容；用户删除的素材也不能自动补回，测试同时覆盖改稿、删除、重复装配与旧版公式容器
