# 问题阶段怎样一次规划并按需补齐

完整材料树 → 首轮同时规划第 0 章与正文问题 → 脚本检查来源去向和字段 → 有缺项才小范围补齐 → 保存本阶段结果

## 每个节点怎样有明确去处

正文、证明、图表、公式和核心代码交给具体问题，有用元数据交给 q.0，导航与容器记录结构用途，辅助资料说明负责问题与查阅用途，明确广告记录排除原因，同内容表示关联已有去处，未知用途继续列为缺项

材料去向明确率与应讲解内容分配率均由 source_disposition.py 按原始材料范围重算，不用父问题引用整棵树来凑覆盖，新增用途不遮住问题字段里的已有引用

## 缺项怎样补

missing-index.json 保存完整缺项编号与按分支压缩的读取入口，补齐只处理这些来源、缺少第 0 章与明确字段错误

需要讲解的缺项合并到已有问题、加入第 0 章或插入新的正文问题；响应只返回修改块，脚本合并后重新计算，没有缺项就不请求补齐模型

## 旧实现放在哪里

archive/question-planning-before-first-pass-20261019 保存旧提示词、检查器、输入压缩器和原调用主体，活动框架仅保留一套执行器；原有正文、材料、历史与笔记不因实现同步而重写，05-test 保持原样

工作副本在进入阶段时同步公共实现，替换前把旧脚本保存在 runtime/framework-history，已完成旧产物继续按其原始版本读取

## 下一阶段怎样承接

章节规划读取问题树的职责、来源和依赖，保存书、章、节标题和 question_ids；父问题负责整体目标，具体问题在所属小节展开，每个问题只能有一个归属

脚本逐项核对全部问题的归属、重复次数与前置顺序，标题的来源与前置标题由脚本推导；缺项使用定向修改块补齐，第 0 章保留 0. 与 0.1.，正文从 1. 开始

## 怎样单独运行一个阶段

```powershell
python -m lessonweave plan <项目目录> --stage questions
python -m lessonweave plan <项目目录> --stage chapters
```

这两个入口只运行所选阶段，不自动继续写作，来源与用量保存在同一项目的阶段目录和 runtime 中
