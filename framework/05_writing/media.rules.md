# 素材怎样独立讲清又跟随正文

规范版本为 media-1.0，公共字段由 media-resource.schema.json 约束，写作提示词由 media_contract.prompt_rules 提供，确定性检查由 media_contract.check 执行，阅读器使用 reader/media-renderer.js 与配套样式

## 每项素材保留什么

| 字段 | 用途 | 检查 |
| --- | --- | --- |
| id | 当前展示块的唯一位置 | 沿用正文块 ID 检查 |
| kind | 决定九类素材的渲染方式 | Schema 限定类型 |
| caption | 解释当前展示对象 | 不能为空，编号由阅读器按章节与出现次序计算 |
| source_refs | 保留实际来源 | 至少一项，来源索引存在时逐项检查 |
| 素材字段 | 保存真实文件、表格、公式、源码或模型网格 | 检查本地文件、表格列数、模型索引及实际代码行号 |
| guide | 保存独立讲解 | 按通用或代码专用 Schema 检查 |

同一素材可以在不同问题附近再次出现，每次使用独立正文块 ID，来源 ID 继续相同，覆盖统计继续按来源去重，展示次数与覆盖率分开计算

## 八类通用素材怎样讲

图片、表格、Mermaid、公式、模型、视频、音频和交互内容先显示本体与编号题注，再显示 reading_guide、components、explanation、takeaway 四部分

components 用直接展开的 BP 列表说明组分，explanation 用自然段展开过程、比较、计算或推导，formula 只在必要时提供，素材本体在自己的讲解范围内置顶，读者可以调高、放大和缩放，视频与音频保留真实时间定位，交互通过本地 HTML 运行，模型从实际网格构建

## 代码怎样讲

line_annotations 保存 line_start、line_end、role、sentence，sentence 是自然连贯的短句，代码全文只展示一份，空行可以没有行注，每个有内容的源码行都应有注释与讲解归属

overview 用 premise、action、result 三段说明整个代码块的功能，segments 把完整代码按功能分段，每段保留四部分

- 综合讲解使用 premise、action、result，说明这段功能在什么条件下怎样工作并得到什么
- 关键组分使用一张完整表格，owner 说明所属类或函数，name、type、default、purpose 与真实行号说明输入、状态和输出
- 核心逻辑说明调用者怎样使用功能、各对象怎样协作及结果为何符合条件，源码逐行职责由行注承担
- 理解结论用 conclusion 与 relation_to_whole 总结该段作用及其与整体功能的关系

分段作为代码块的子讲解编号，源码随阅读高亮，summary 用 answer、collaboration 总结整个代码块，runs 只保存执行器已经提供的实际输入输出，页面标题固定为实际运行，执行结果缺省时使用空数组

## 检查做什么

脚本检查字段、来源存在、实际文件、表格形状、模型索引、代码行范围、非空行注释覆盖、分段归属与重复、作者文字中的明确禁用表述，检查结果只返回问题列表，不增加模型请求、逐句审查或自动返修循环

这些结果证明格式和引用关系可用，语义是否讲透仍需要结合实际正文判断，脚本不会把映射达到 100% 当作语义已经完整的证明

旧正文块继续使用已有渲染，只有带 guide 的新素材进入新渲染器，笔记仍按原问题键保存，本次同步不重写正文，不改 05-test
