# 独立检查怎样保持轻量

正式入口先完成全部生成，再由独立脚本读取落盘文件检查一次，有问题时集中做一轮批量修复，最后复核实际改动，无问题时跳过修复模型

| 检查对象 | 脚本怎样检查 |
| --- | --- |
| 材料树 | 重新核对 Schema、原始内容保留、本地对象和来源引用 |
| 问题树 | 重新计算材料节点覆盖，检查来源 ID、前置关系与学习顺序 |
| 章节 | 问题需要恰好分配一次，标题及书章小节层级符合规则 |
| 每问 C 结果 | 必填字段、所属问题、规划与讲解对应、材料映射完整且来源存在 |
| 作者文字 | 用正则定位明确违反写作规范的句式、中文句号和裸材料编号 |
| 公式、图表、代码等素材 | 检查类型 Schema、本地文件、引用、代码行范围及讲解归属 |
| 译文 | 每条原句有中文与英文，原句原样保留，不对原文和忠实译文执行作者 lint |
| 练习 | 数量符合预分配配额，答案索引位于实际选项范围内 |
| 术语 | 名称字段、三段内部细字段和必要值齐全，缩写与英文全称不同 |
| 承接 | 每节恰好一份承接，字段完整并通过作者 lint |

程序先处理确定的格式转换，再把其余具体问题及对应字段集中处理，模型只返回受影响字段的改动，保留其余内容，缺少材料解释时补进正文，修复结束后不启动新一轮内容修改

一轮修复指一次集中处理全部已发现的问题，repair_batches.py 按执行容量把整份文档的改动装入并行请求，共用材料在每个请求内只出现一次，同一文档只进入一批，模型返回后统一应用和复核，大批漏译沿用翻译模型，每条漏译在这一轮只请求一次

媒体字段返修会携带实际媒体 Schema，普通句式改写继续只提供所需的局部内容，返修结果仍由脚本重新检查，新增未通过项继续保留在报告中

修复装包默认以 450000 个输入 UTF-8 字节和 60000 个待改字段 UTF-8 字节作为调度目标，可通过 LESSONWEAVE_REPAIR_BYTES 与 LESSONWEAVE_REPAIR_CHANGE_BYTES 调整，超出目标的完整单份任务仍单独保留，这些参数不裁剪材料，也不改变检查分母

结果保存到 `05_writing/checks/independent-before.json`、`independent-after.json` 和 `batch-repair.json`，保留剩余问题与实际调用次数，正文质量评分和独立 AI 语义审查保持关闭

术语生成使用紧凑 JSON，字段名称、结构、空字段和三段内部细字段继续保留，模型原始响应单独保存，磁盘上的便于阅读版本不计作生成节省

资源文件沿用材料树已声明的读取范围，源码和文章读取实际正文，字体数据及附件按已登记的文件类型、路径、大小和项目用途进入讲解，完整原文件继续保存在本地，修复输入会保留原任务的全部引用编号并记录调整前后的字符数

图片输入按实际文件类型判断，并沿用解析器已经提供的模型预览，Mermaid 保留语法换行，合并的源码行范围仅在已有片段连续且完整覆盖时展开为对应引用，这些确定转换由脚本执行

代码仓库的规划输入超过执行端明确给出的字符上限时，框架移除重复定位数据，全部节点、声明、动作和实际内容继续进入规划，完整定位仍保存在材料树中，源码读取始终按照 `00_source/source.json` 登记的实际仓库目录定位

翻译由 translation_batches.py 处理，源码行保持原样，自然语言原句先去重，再按可配置的输出容量目标分批，默认每批原句与编号约 24000 个 UTF-8 字节，通过 LESSONWEAVE_TRANSLATION_BYTES 调整，条目保留完整，模型只生成译文，脚本填回原句并保持既有三个字段
