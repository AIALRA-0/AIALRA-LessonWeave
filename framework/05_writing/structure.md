# 怎样从已经确认的正文结构接成完整读本

公共实现和规则保存在 framework，用户材料与生成结果放在 LESSONWEAVE_DATA，当前正文使用 continuous-unit-2.0，媒体沿用 media-1.0，媒体字段与展示规则见 media.rules.md

## 当前确认的流程怎样走

保存原件与资源 → 解析完整材料树 → 同时规划第 0 章和正文问题 → 独立编排章节 → 每问在一次调用中规划并写作，翻译并行进行 → 根据实际答案生成承接 → 脚本检查并按需做一轮批量修复 → 装配、定位和导出

同次生成的实测已经验证短骨架加连续讲解的路径，规划条目保留实际材料引用，一条规划可展开多组讲解，必要补充按需提供，框架通过真实引用统计材料映射，映射达到 100% 说明引用完整，语义是否讲透还需要结合实际正文判断

翻译在解析得到稳定原句后即可并行执行，译句沿用原句位置并按材料版本复用，写作读取原始材料，翻译与逐问正文使用各自职责明确的请求

## 每个完整问题怎样展开

一个问题依次包含展开后的问题段、多组讲解、本段总结和一个笔记框，读者界面直接显示编号标题，问题段、讲解组、升华段这些内部角色留在 Debug 中

每组先在短骨架里定好标题、核心回答、展开步骤、来源和承接，claim 只生成一次，body 把条件、机制、推导和实例连续讲清，supplement 按需补充，允许为 null，阅读器省略空补充，旧读本仍可读取 reasoning 与 grounding

result.answer 直接回答当前问题，result.generalization 提炼在适用条件下可以迁移的结论，后续问题由承接阶段负责，来源绑定继续指向实际渲染的正文块，素材就近放入 resources

## 非文本素材怎样接入

图片、表格、Mermaid、公式、模型、视频、音频与交互内容使用独立的 reading_guide、components、explanation、takeaway，素材本体与编号题注在讲解范围内置顶，关键组分直接展开，媒体讲解与正文在同次写作请求中生成

代码使用专用结构：自然连贯的行旁短注、premise/action/result 综合综述、多个功能分段、整体总结与真实运行输入输出，每段只显示综合讲解、一张关键组分表、核心逻辑和理解结论，完整源码只展示一次，分段与组分沿实际行号高亮

media_contract 检查 Schema、实际文件、可用来源索引、代码行范围与覆盖、分段重复、表格列数、模型索引和明确的作者表达问题，检查只返回具体问题列表，不增加模型请求或自动返修循环

## 正文之后还要补什么

承上启下、核心问题、内容讲解、内容总结、易错点和问答使用同级标题，术语表位于右栏，承接标题固定为承上启下，carryover 根据前节实际内容写一段，premise 与 question 合成启下的一段

核心问题使用普通列表，内容总结按核心问题逐项直接回答，易错点使用直接相关的前提与问句，短段落澄清问题核心并说明条件，练习默认四道单选加一道简答，题位由脚本在写作前分配，整节合计四道单选和一道简答，答案通过核对按钮显示


## 怎样保持写作和检查轻量

写作提示词要求作者明确每个核心命题的主体、行为或状态、对象与成立条件，脚本只集中提示明显的内部编号泄漏、禁用句式和可能过度压缩的表达，合法共享主语保持自然，DDParser 与逐句专项审查保持关闭


## 正式调度器现在怎样执行

正式默认入口已切换为 continuous-unit-2.0，材料树直接进入问题规划，正文与附加内容同次输出，翻译按原句去重并行进行，两段承接在实际正文完成后集中生成，末尾只做格式与引用脚本检查，具体输入、输出、职责和取舍见 lean-flow.md

旧的多轮写作调度与独立 AI 审查入口已经归档，兼容已有读本的数据读取代码继续保留，原有正文、笔记与 05-test 保持原样
