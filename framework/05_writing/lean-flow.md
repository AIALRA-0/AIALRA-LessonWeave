# 每次调用为什么必要，哪些输入已经省掉

正式默认入口为 lessonweave.pipeline.run → lessonweave.lean.run，版本为 lean-c-1.0，旧执行入口已经归档，默认入口不进入旧全局信息点清点、分节清点或独立 AI 内容评分，全部生成后执行一次独立脚本检查，有具体问题时只做一轮批量修复

## 哪些内容应该一起生成

每个问题使用独立上下文，C 调用内先生成多条讲解规划，再生成问题段、多组讲解、当前答案和可迁移结论，媒体讲解、易错点、分配的练习和本问术语定义一起输出，写作者在输出末尾已经知道实际写了什么，无需再把正文交给另一个请求重读

内容总结直接使用 result.answer，脚本负责按问题顺序排列，练习配额在写作前由脚本分配，每节合计默认四道单选和一道简答，术语最后在同一响应内填写完整定义，脚本按英文全称与中文名称合并重复词条，原始逐问定义继续保留，合并过程没有模型调用

同名词条在并行问题中仍可能分别输出，脚本合并节省展示和后续输入，重复定义的输出 token 已经产生，当前实现没有把这部分记录成节省，词义冲突继续保留在 checks.json，不自动重写定义

## 承上启下在哪里生成

执行位置是 lessonweave/lean.py 的 c_bridges，所有正文完成后，脚本将各节实际答案与本节标题、核心问题、结论组成紧凑边界输入，模型按每批 16 节返回 bridges 数组，最多并发 7 批，脚本合并所有已完成批次

每项输出包含 section_id、carryover、premise、question，carryover 显示为承上一段，premise 与 question 合成启下一段，界面标题固定为承上启下，磁盘保存于 05_writing/work/bridges.json，并在各节目录保存 bridge.json

前置条件是相邻节实际正文与答案已经完成，章节标题或待讲规划不能冒充前文已经讲清的结论，首节没有前文时直接从材料情境起笔

章节并行生成时，正文之间保持并行，承接在完成后集中输出，正文和原材料都不重新传入，纯串行时可以把前节实际结果交给当前写作调用顺带生成承接；当前默认实现统一采用并行后集中生成，便于复用与恢复，暂未增加另一套串行运行模式

## 为什么翻译单独生成

翻译直接读取去重后的自然语言原句，输出 resource_id、chinese、english，模型把原文所在的显示字段填写为 null，脚本按编号填回原句，磁盘产物继续保留两个完整显示字段，源码行原样保留

翻译无需等待正文，可与写作并行，同一句被多个问题使用时只请求一次，复用记录同时核对原句文本，原句发生变化时才重新翻译，当前实现没有把译文作为第二份写作输入

翻译使用 translation_batches.py 为输出预留容量，默认按约 24000 个 UTF-8 字节的原句与编号分批，调度参数 LESSONWEAVE_TRANSLATION_BYTES 可以调整，每批保留完整条目，实际调用数及问题保存在 translation-batches.json，调用回执继续逐项记录

独立翻译与讲解都要理解原句，但职责不同，这次保留的原句输入分别服务忠实转换与解释推导，分离翻译可以避免多个问题重复输出同一译文，也让翻译后端可以单独配置

## 检查怎样保持轻量

脚本检查 Schema、实际引用、规划与讲解对应、材料映射、素材存在、代码行范围、题目数量及答案索引，检查结果保留真实状态，确定的格式转换由脚本集中处理，其余具体问题按文档和执行容量组成同一轮并行改动请求，共用材料去重，模型只返回增量改动，所有结果统一复核，无问题时跳过修复模型，没有独立 AI 内容评分

一轮批量修复可以包含多个按容量装包的请求，内容文档只分配到一个批次，译文继续使用配置的翻译模型，每条漏译在这一轮只请求一次，所有结果统一复核，模型调用数与修复轮数分别记录

脚本可以发现引用缺口、缺字段与结构缺失，事实错误、重要条件未解释或推导不充分仍属于内容问题，映射达到 100% 时也要根据实际正文判断质量，用户可以直接在完整样章中审核

## token 与耗时怎样记录

runtime/calls 保存每个请求的 prompt、schema、原始响应、格式转换与 usage 回执，runtime/usage.json 汇总输入、输出、缓存输入与各请求耗时，缓存输入属于总输入的一部分，汇总时不重复相加

模型请求墙钟、各请求耗时之和、脚本装配时间分别显示，本轮开发和页面调整时间不混入生成耗时，既有正文的历史生成用量单独显示，本轮复用正文的新增生成用量为零

提示缓存要求可复用输入前缀保持匹配，当前实现把短而稳定的规则放在动态材料之前，实际命中情况按回执记录，不填预计命中量，官方说明见 https://developers.openai.com/api/docs/guides/prompt-caching

本轮轻量检查规则与产物位置见 light-checks.md，术语输出采用紧凑 JSON，原有名称、层级、空字段及三段内部细字段全部保留


## 当前配置来自哪些实测结果

正文默认并发 144，同样 177 题的实测用时从 48 路的 38.2 分钟降到 16.0 分钟；177 路反而回升到 24.2 分钟，因此没有继续提高默认值

英译中使用 Flash 非推理，每批约 24000 UTF-8 字节、并发 12；同样 8652 条自然语言的冷生成用时为 130.1 秒，正文和翻译并行执行，译文缓存与 API 输入缓存分别记录

术语继续在正文同次生成，已有共通词义复用完整三段，特殊词义另存；六问对照中，完整术语拆开生成既没有缩短总等待，也增加了输入与输出，因此不增加独立词义登记阶段

阅读覆盖率从实际讲解引用展开已有合并来源，没有独立文字的容器关联到已讲解子项；0 字节文件保留名称、路径及所属问题，记录为没有正文的上下文，不虚构讲解内容
