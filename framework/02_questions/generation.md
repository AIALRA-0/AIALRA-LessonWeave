# 怎样从完整材料树一次规划第 0 章和正文问题

本阶段只生成问题、问题职责、学习依赖和材料用途，不生成答案、讲解、写作规划、术语定义或逐事实清点

## 首次怎样把材料安排完整

读取完整材料树及原件，先沿全部主体分支了解材料的主线，再按理解关系组织问题，不按文件或符号机械逐个出题，不设置问题数量、节点数量或文件大小上限

首轮同时规划正文与第 0 章：有用的作者、标题、日期、版本、出处、引用方式、DOI、arXiv 标识和许可范围等进入 q.0，没有可用元数据时不创建第 0 章；第 0 章与正文使用完全相同的问题字段，只生成问题

问题统一使用 q.root、q.0、q.0.1、q.1、q.1.1 等数字层级，premise 直接引出 question，两者连成一行自然问句，question 以中文问号结尾；intent 说明本题具体解释什么，以及读者应当理解什么

父问题统领目标，具体叶子负责实际内容；learning_order 恰好包含全部叶子，depends_on 只引用其中更早的叶子，不把父目标当作已经学过的知识

## 每份材料应当去哪里

- 正文、证明、公式、图表和核心代码进入负责解释它的具体问题
- 有用元数据进入 q.0 的具体问题，不能用第 0 章收容正文遗漏
- 导航、章节标签与容器标记为 structure，作用是定位和组织，其下正文仍需独立分配
- 辅助资料可以标记为 reference，但必须指向具体叶子并说明查阅用途，不能把未读正文整包改成查阅材料
- 明确广告或无关推广标记为 excluded，写清排除原因，原件继续保留
- 同内容关联由脚本沿解析结果和符号链接计算，字符不同的表示与原图继续保留

source_nodes 使用材料树中的真实编号，选择分支表示使用其后代；同一来源可以服务多个问题，禁止让一个叶子引用整棵材料根节点来凑覆盖，父问题引用也不代替叶子负责

dispositions 的 extent=node 只标记本节点，subtree 标记完整分支；question_ids 只引用真实叶子，旧用途记录不得遮住问题字段里的实际引用

首次返回 initial.schema.json 中的 questions、metadata、dispositions，metadata 如实登记原件是否有可用元数据及对应来源，运行路径和覆盖率由脚本计算，不自行填写

## 脚本检出缺项后怎样补

先读 missing-index.json，再读当前问题的相关职责，只处理缺失来源、缺少第 0 章与明确格式错误，不重写已完成问题

需要讲解的遗漏只走三条路：source_additions 并入已有叶子；new_questions 加入第 0 章；new_questions 插入职责独立的新正文问题

新问题给出 parent_question_id 和 after_question_id，问题字段与首次相同；question_updates 保留已有 ID 和子树，只修必要字段；learning_order 无需修改时填空数组，修正时返回全部叶子的正确顺序

只返回 patch.schema.json 指定的修改块，不写答案或质量审查报告；脚本重新计算真实差集，有缺项继续补，没有缺项就完成本阶段

## 正式文件保存什么

questions.json 保存完整问题树、元数据事实、用途记录与当前覆盖汇总，history 保存每次实际候选及逐节点 coverage.json，missing-index.json 保存尚未分配的来源和具体格式问题

材料去向明确率是已经登记明确用途的节点数除以完整材料节点数，应讲解内容分配率是已经由具体叶子负责的应讲解节点数除以应讲解节点总数，两项均按冻结材料计算，未知用途继续列为缺项

原始材料、来源差异、历史和用户笔记继续保留，当前问题规划不调用全局清点或 AI 审查
