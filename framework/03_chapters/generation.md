# 怎样把全部问题组织成书

03_chapters 只规划成书的标题与章节分配，不生成正文

输入是已经完整分配来源的问题树、每题职责、学习顺序与前置关系，不重复输入整份材料；q.0 同属问题树，第 0 章排在正文之前，显示 0. 与 0.1. 等编号，正文从 1. 开始，没有 q.0 时不生成空第 0 章

## 怎样安排章节和小节

1. 冻结已经通过检查的问题树，保留它的问题版本与材料版本
2. 从学习目标出发，沿问题的 depends_on 安排先后，把共同建立一项理解的相近问题放进同一节，再把递进的小节组成一章
3. 先检查每章每节实际包含什么，再拟定能概括其共同核心的标题，不用其中某个局部问题代替全章标题
4. 模型用 premise 与 question 表达一行完整标题，question 以一个中文问号结尾；脚本将两者拼成 title 并添加目录编号
5. 对问题树中的每个节点指定唯一归属，书级目标可以放在书标题，章级或节级目标放在能够统领全部子问题的标题下，具体问题只在对应小节展开
6. 父问题用于引入整体目标和收束已建立的理解，不把各小节的讲解再写一遍，同一具体问题在其他位置需要用到时只回指其原有归属
7. 交给 build_chapters.py 核对分配与顺序，通过后发布 chapters.json

## 怎样保证恰好覆盖 100%

分母是冻结问题树的全部节点，包含父问题和具体讲解问题

每个 question_id 在整棵标题树的 question_ids 中必须出现一次，脚本逐项列出漏掉或重复的问题，覆盖率应达到 100%，分配次数应与问题节点总数完全相等

父问题所分配的标题必须包含其全部子问题的归属，具体问题在章、节以及节内的排列都要满足原来的前置关系

目录不删改问题与材料之间的对应，每个标题的 source_nodes、requires 和实际学习顺序由脚本重新推导，逐问的原始来源与依赖保存在覆盖报告中

问题只分配一次，材料仍可由不同问题从不同角度使用，材料引用不做去重删除

## 哪些文件用于保存结果

| 文件 | 用途 |
| --- | --- |
| chapters.json | 当前标题树，保存全书、章与节的标题，以及每个问题的唯一归属 |
| generation.schema.json | 模型只返回 tree，每个标题只填写 id、kind、premise、question、focus、question_ids 和 children |
| chapters.schema.json | 检查保存后的完整目录，包含标题、问题归属及脚本补齐的来源、顺序和依赖 |
| patch.schema.json | 模型只返回需要调整的标题与归属，不填写脚本派生的字段 |
| build_chapters.py | 检查完整分配、前置顺序和来源对应，再保存通过的版本 |
| test_chapters.py | pytest 检查，每项测试上方说明会检查什么 |
| history/revision-编号/chapters.json | 当时通过检查的标题树 |
| history/revision-编号/coverage.json | 全部问题的归属、原始材料引用与跨标题的前置关系 |

运行方式为 python 03_chapters/build_chapters.py 候选文件路径，外层 agent 负责拟定与审阅标题，脚本负责检查分配和关系

## 怎样判断标题是否概括准确

把该标题下所有小节与问题一起读一遍，确认标题能说清它们共同建立什么理解，既不遗漏主要内容，也标题的范围与实际分配内容一致

Schema 检查标题格式，外层 agent 按实际问题检查标题含义，查看归属列表时可以从标题回到问题，再回到冻结的原材料


模型只按 generation.schema.json 返回 tree，按实际阅读顺序排列章、节和节内的 question_ids，不输出 learning_order、source_nodes、requires、完整 title、覆盖率、验证状态、运行编号或文件路径，连空占位也不输出；脚本将目录的实际排列记录为学习顺序，从已有问题继承来源与依赖，并按 chapters.schema.json 检查完整存储结果；书根 ID 使用 book，第 0 章与正文的显示编号由脚本添加

脚本检出遗漏、重复归属或顺序冲突后，只发送当前目录、相关问题和具体缺项，按 patch.schema.json 返回修改块，已完成内容保留，全部问题各归属一次后完成本阶段
