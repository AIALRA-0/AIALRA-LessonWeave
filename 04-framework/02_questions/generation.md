# 怎样从材料树生成完整问题树

先生成问题树，再根据学习依赖合并相近问题、编排章节和决定讲解分段

这一阶段保存问题与来源，不提前生成教材正文，也不把正文长度反过来当成问题边界

## 外层 agent 怎样拟定问题

1. 读取通过检查的材料快照，保留材料路径和运行编号，从整份材料确定学习目标与起点
2. 围绕学习目标确定几条理解路径，再递归拆成具体问题，独立路径可以在共享目标、字段约定和材料版本之后并行拟定
3. 先把情景和疑问写成一句连贯的话，再在自然停顿处分为 premise 和 question，前半段交代条件并保留逗号等衔接标点，后半段直接提出由此前提引出的未知，连读时不重复条件，不添加“已知或情景”这类标签，也不强行套用“因为……所以……”
4. 用 intent 说明回答这一问后新增的理解，用 depends_on 指向前面已经讲过的具体问题，父问题表示尚待建立的整体认识，不能当作已经学过的知识
5. 为每个具体问题选择实际 source_nodes，图片、标注、图注与正文可以一起使用，同一材料可以支持多个问题，同一问题也可以综合多个材料节点
6. 逐个检查材料是否已有具体问题负责讲解，缺漏时补充理解步骤或修正来源选择，不能只让总问题引用整棵树来凑覆盖
7. 审阅情景是否准确、未知是否清楚、子问题能否逐步回答父问题，以及材料是否真的支持问题所需的讲解，再交给脚本检查

例如，premise 写“如果每次只放一个宏，而已经放下的宏又会限制后续位置，”，question 接“系统需要记住哪些信息，才能继续决定下一个宏放在哪里？”，question 以一个中文问号结尾，页面同一行展示，阅读时是一句完整的问话

问题不依赖固定学科模板，文章可以围绕观点、经历、证据或叙事展开，代码先解释系统目标、数据路径和验证方法，再按需要深入实现

## 脚本怎样检查并发布

外层 agent 提供候选 JSON，build_questions.py 按 questions.schema.json 检查字段，并重新读取冻结的材料树

全量模式必须使用材料树根节点作为 source_roots，分母包含所有节点，不删除页眉、元数据、资源或解析疑点

覆盖率只计算叶子问题 source_nodes 中的直接引用，每个材料节点至少出现一次才通过，父问题引用不计入覆盖

- 材料节点覆盖率 = 至少被一个具体问题引用的材料节点数 / 全部材料节点数，必须达到 100%
- 映射次数比例 = 具体问题的直接引用总次数 / 全部材料节点数，可以超过 100%，同一个问题内部不重复计算同一节点

检查还会拒绝不存在的来源、重复问题、缺失或空白的情景、指向后面或整体目标的前置引用，完整语句重复，以及与树不一致的讲解顺序

通过后，脚本把问题树和逐项反向映射报告保存在 history/revision-编号 中，再更新当前 questions.json，失败候选不能覆盖上次通过的结果

运行方式为 python 02_questions/build_questions.py 候选文件路径，候选由已经存在的外层 agent 负责拟定，本项目没有另加模型调用器

## 每个文件保存什么

| 文件 | 保存内容 |
| --- | --- |
| questions.json | 当前通过检查的问题树，包含情景、问题、理解用途、来源、前置问题、学习顺序与覆盖汇总 |
| questions.schema.json | 所有问题共享的字段约定，premise 和 question 都必须是非空白字符串 |
| build_questions.py | 检查候选、计算双向映射并发布通过的结果 |
| test_questions.py | 普通 pytest 测试，每项测试上方写明检查什么 |
| history/revision-编号/questions.json | 当时通过检查的问题版本 |
| history/revision-编号/coverage.json | 每个材料节点对应的具体问题、分类统计与未覆盖节点 |

## 怎样理解 100% 的范围

100% 表示当前冻结材料树的每个节点都有具体问题映射，不表示教材已经写完，也不表示自动证明了语义讲解充分

论文与网页的正文、图表和来源说明都参与检查，代码基于当前架构树逐层组织问题，资源可以按真实用途共同讲解，不能为数百个同类字体编造数百个重复问题

代码仓库中的 PDF 和 ZIP 附件目前只映射入口、用途与证据边界，内部正文尚未解析，因此不能宣称附件正文已得到完整讲解，后续展开附件或代码文件形成新材料版本时，应重新生成或补齐映射

页面提供问题回到材料、材料反查问题和逐项报告，供审阅者判断映射是否贴切，不能用映射数量代替这项判断

同一候选和材料快照会得到相同的结构检查与映射统计，不同 agent 拟定的问题文字可能不同，语义质量仍由外层 agent 审阅，Schema 不承诺自动判断问题好坏
