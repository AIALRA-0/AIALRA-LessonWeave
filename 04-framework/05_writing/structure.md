# 05 怎样围绕原材料写清每个问题

lessonweave/pipeline.py 读取已通过检查的问题、章节和承接计划，按小节清点原材料，再为每个完整讲解单元建立独立写作请求，各单元可以并行生成

公共实现和规则保存在 04-framework，运行材料与结果放在 LESSONWEAVE_DATA，每个新项目保存独立的阶段规则副本，既有项目保持创建时的规则内容

## 每节按什么结构阅读

承上启下、核心问题、内容讲解、内容总结、易错点和问答使用同级标题，术语表放在右栏，标题比正文更大并加粗，普通正文保持自然排版

承上启下使用固定标题，正文依次显示三段：04 保存的完整问句、承上段、启下段，核心问题使用普通无序列表，内容讲解按 X.1、X.2 等编号显示对应问题标题

一个讲解单元包含问题段、讲解段和升华段，问题段补足情景与条件，讲解段解释材料中的事实、过程、图表、数值和限制，升华段回答当前问题并引出后续需要理解的边界，讲解可使用多个自然段、列表、代码和图片

每个完整讲解单元结束后提供一个“写下这一段的理解”笔记框，用户可以自由记录，内容总结按核心问题逐项直接回答，易错点用带条件的问题标题引出简短而对题的澄清

练习通常提供四道单选和一道简答，允许三到五道单选，简答恰好一道，答案通过核对按钮显示，术语解释保留定义、围绕当前材料的解释和理解边界，名称格式由 terminology.rules.md 约束

连续叙述保持同行，排比条目在冒号后换行并缩进，positive_writing.py 检查作者新写内容中的禁用句式，原文、忠实译文、代码及已确认固定题干保持准确

## 怎样确认每个信息点都讲清

每个资料条目先清点信息点，信息点包含实际原句或区域、负责的问题和需要解释的 checks，作者提交正文及 block_ids 对应，独立审查再逐条核对原材料与实际正文

脚本核对每条 checks 的审查索引、实际正文块、责任归属和版本，条目内的应讲信息点全部通过后 explained 才为 true，覆盖率由 teaching_coverage.py 和整书检查重新计算，作者提交的百分比不作为结果

清单负责查漏，理解关系负责组织正文，一个自然段可以解释多个相关信息点，同一图片也可在不同问题附近再次展示，重复展示保留共同来源，覆盖分母继续去重

材料清点与正文审查分别使用独立请求，审查同时核对清单有无漏项、图表含义、数值条件、正文连贯性、易错点、练习和术语，失败状态和实际审查快照继续保存

## 怎样集中修复并控制轮次

每个单元先生成一次，全部相关检查完成后集中反馈，下一轮批量修改受影响的单元，格式转换单独执行并留档，相同输入的已完成请求复用结果

初稿为第 0 轮，默认最多进行三轮修复，配置上限为四轮，恢复任务沿用原轮次，达到上限后保留完整预览与真实问题清单，响应不确定的请求先保留现场，避免盲目重复提交

## 实际产物保存在什么位置

- 05_writing/work/sections 保存每节的 context、source-pack、inventory、逐问正文、附加内容、审查、覆盖与各轮快照
- 05_writing/preview 保存当前完整待审书稿，preview-book.json 提供目录入口，只有实际检查通过才发布 book.json
- 05_writing/source-location 保存实际 PDF 坐标、网页 DOM、源码行号和图片区域，缺少 OCR 时保留真实区域及实际状态
- 05_writing/reading-package.zip 保存可移交的书稿、阶段结果与原材料，格式由 reading-package.schema.json 规定，用户笔记由宿主独立保存
- runtime/calls 保存独立模型请求、原始响应、格式转换和实际用量回执，runtime/usage.json 汇总 token 与缓存记录
- runtime/state.json 保存任务轮次、进度和集中反馈，服务任务队列与个人笔记由站点 SQLite 保存

缓存输入属于输入 token 的一部分，汇总时单独列出而不重复相加，Codex 通道使用已登录账户的订阅额度，回执未提供货币账单时保留实际 token，费用保持未知
